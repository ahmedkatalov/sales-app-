# Подключение ИИ-ассистента (AI-склад)

Ошибка в чате **«ИИ пока не подключён…»** или `403 Access denied by security policy`
означает НЕ баг приложения, а то, что **сеть сервера не пускает к OpenRouter/OpenAI**
(эти сервисы заблокированы в регионе, где стоит сервер). Касса, склад, меню, продажи,
финансы работают без ИИ — это отдельная функция.

Чтобы ИИ заработал, нужен **достижимый канал** к провайдеру. Выбери один вариант.

## Что уже настроено
- `OPENAI_API_KEY` — ключ ИИ (у тебя, судя по логам, задан).
- Почта и остальной трафик идут напрямую и от прокси НЕ зависят.

## Вариант 1. Релей (проще всего, без своего прокси)
Взять OpenAI-совместимый релей, который **доступен из региона сервера** и сам ходит к
OpenAI/OpenRouter. Прописать его адрес и ключ в окружении сервиса **backend**
(`docker-compose.yml` → `environment:` или `.env`):

```yaml
    environment:
      - OPENAI_API_KEY=<ключ от релея>
      - OPENROUTER_BASE_URL=https://<адрес-релея>/v1
```

Все запросы ИИ пойдут на этот адрес — прокси не нужен.

## Вариант 2. Рабочий прокси/VPN только для ИИ
Если есть рабочий прокси/VPN с зарубежным выходом — направить через него ТОЛЬКО трафик ИИ
(почта и остальное останутся напрямую):

```yaml
    environment:
      - AI_PROXY_URL=socks5://ЛОГИН:ПАРОЛЬ@host:port   # или http://host:port, или https://
```

Поддерживаются `socks5://`, `http://`, `https://` (логин:пароль — по желанию).
ВАЖНО: у прокси должен быть **зарубежный выход**. Иранский прокси упрётся в ту же
блокировку. Прежний `213.176.114.68:1080` лежал — его надо поднять заново или заменить.

## Вариант 3. Сервер в незаблокированном регионе
Перенести backend на VPS в регионе без блокировки OpenAI/OpenRouter — тогда ни релей,
ни `AI_PROXY_URL` не нужны, всё пойдёт напрямую.

## После изменения
```bash
cd /opt/sales-app && git pull && docker compose up -d --build
```
Открыть «Помощник» → задать вопрос. Если ответит — готово. Если снова про блокировку —
канал (релей/прокси) недоступен или сам режется; проверить его отдельно.

## Диагностика прямо на сервере
```bash
# внутри контейнера/на хосте backend:
curl -s -o /dev/null -w "%{http_code}\n" https://openrouter.ai        # 200/301 = доступ есть; 403/таймаут = блок
curl -s -x socks5h://host:port https://openrouter.ai -o /dev/null -w "%{http_code}\n"   # проверить прокси
```
